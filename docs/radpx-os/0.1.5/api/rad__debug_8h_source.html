4 // Debug-scaffolding categories.
5 //
6 // Each macro gates a self-contained set of diagnostics that were used to root-cause the SMP
7 // scheduler "ghost double-execution" bug (a task's user frame iret'd on a second core while it
8 // was legitimately scheduled on another, sharing one tss_rsp0 -> kernel-stack corruption). They
9 // are all compiled out by default; enable a category at CMake configure time to compile it back
10 // in, e.g. `cmake ... -DRAD_DEBUG_SCHED_TRACE=ON`:
11 //
12 // RAD_DEBUG_SCHED_TRACE scheduler/ghost diagnostics + task-identity fault dumps
13 // (RAD_USER_NO_TASK, GHOST snapshot, RAD_RESUME_NO_TID, rad_dbg_*
14 // helpers, RAD_TSS_MISMATCH, RAD_STACK_ALIAS, RAD_RT_ENTER, the
15 // faulting-process identity block in the exception reporters)
16 // RAD_DEBUG_WATCHPOINT hardware DR/#DB watchpoint infrastructure (x86_debug_entry on IST[0],
17 // x86_cpu_arm_frame_watch, x86_debug_dispatch, RAD_WATCH_CORRUPT)
18 // RAD_DEBUG_VM_TRACE VM/page-ownership diagnostics (RAD_PAGE_STOLEN, RAD_PREMATURE_FREE,
19 // RAD_PF_ON_RADTERM_STK, g_page_owner_pid)
20 // RAD_DEBUG_AUTORUN auto-launch radterm + feed shell commands (userland/service test
21 // harness; defined on the radterm app and the compositor service)
22 //
23 // The CMake build only defines the enabled categories (as 1); the fallbacks below keep every
24 // `#if RAD_DEBUG_*` well-defined in a plain default build.
